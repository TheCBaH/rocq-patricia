## H1 — Primitive proofs

Dependencies: H0.G.

- [x] **H1.1** `HashTableBits.v` defines chunks, proves the per-chunk bound, proves a normalized 30-bit hash has zero chunk at depth six, reconstructs every normalized hash from its six routing chunks, and proves distinct normalized hashes differ at one of depths 0 through 5.
- [x] **H1.2** `HashTableBits.v` defines bounded popcount/rank and dense-list edits, proves bitmap occupancy is equivalent to the corresponding bit test for every native slot (soundness and in-range completeness), that enumeration is duplicate-free, and characterizes an empty bitmap as absent at every slot. It gives exact single-bit/full-bitmap popcount and rank at every native slot, an exact two-distinct-bit popcount, empty and full occupied-slot enumeration, enumeration length equal to bounded popcount, and proves low-bit masking is exactly the `< slot` filtered prefix of the original occupied-slot enumeration. Consequently rank is the dense length of that routing prefix; scan splitting and before/after-cutoff mask laws expose its exact workers, and every occupied bounded `N` slot is immediately after a prefix whose length equals rank. Adding a routing bit leaves that slot’s rank unchanged, and ordered two-bit routing assigns the left/right dense ranks zero/one. An absent bounded slot now splits the old enumeration at its rank and inserts exactly one element in the bitmap OR enumeration, yielding the matching popcount increment; a present slot has the dual exact deletion split and popcount decrement through `ldiff`. It also proves bounded lookup laws before/at/after insertion plus replacement/removal lookup preservation, insertion/replacement/deletion membership laws, exact valid-index removal cardinality, and slot/child paired replacement and insertion preservation.
- [x] **H1.3** `HashTableBucket.v` defines lookup/set/remove and empty/singleton/many normalization with pointwise update/removal preservation for different equivalence classes, exact hit/miss insertion cardinality, successful-removal cardinality, relation-parametric uniqueness preservation, and equivalent-query lookup congruence. `bucket_set_key_nodup` gives one all-cases update theorem for collision-key equivalence, requiring freshness only when lookup reports a miss.
- [x] **H1.G** Gate: primitive proofs compile and the theorem assumption audit passes (2026-09-15; 286 declarations closed under the global context).

## H4 — Compact-array backend

Dependencies: H3.G.

- [x] **H4.1** `HashTableNative.v` defines the source-modeled persistent sequence interface, fresh-update view, indexed lookup/cardinality laws, and recursively native-child tree/source relation with structural source round trip. Recursive `native_get`, `native_set` and `native_remove` use compact native-child lookup/replacement/insertion/removal at every nonzero-fuel branch and refine their source workers; removal compacts an empty child through source-equivalent `native_branch_remove`. Present/missing-child alignment lemmas connect dispatch outcomes to source. `HashTableExtract.v` separately extracts the modeled-native artifact. This is a list-modeled proof stage, not an OCaml array realization.
- [x] **H4.2** `HashTableNative.v` / `HashTableNativeProof.v` define modeled native get/set/remove and prove refinement for arbitrary related source/native trees. The seeded `native_table` boundary refines source empty/is_empty/get/mem/elements/set/remove, preserves its seed, lifts source validity through modeled set/remove, and inherits source self/equivalent-query update/removal, flattened-binding lookup/membership, equivalence-key enumeration uniqueness, and emptiness behavior. The separately extracted model passes retained-version bytecode/native differentials against extracted source workers. Array-realizer refinement remains separately open under H4.4/H4.5.
- [ ] **H4.3** In progress: `HashTableBits.v` and `HashTable.v` prove every five-bit slot and source routing `child_bit` yield a nonzero bitmap bit strictly below `2^32`, bounded bitmaps reject slots at or above 32, and popcount/rank workers are bounded. `bitmap_ldiff_bit_bound` gives the same 32-bit range contract for every compact branch-deletion bitmap, while `branch_insert_bitmap_bound` and `branch_remove_bitmap_bound` expose those insertion/deletion bounds on executable branch constructors. Bounds for all native-operation intermediates remain open.
- [ ] **H4.4** In progress: `HashTablePrimitives.ml` / `.mli` provide private fresh-copy sequence primitives and `HashMapNative.ml` uses them for a private-array HAMT. `HashTableNativeArrayExtract.v` now binds only the modeled `pseq` interface to those primitives, preserving extracted recursive native workers and native table API. `native_table_of_list` implements first-wins loading and refines source `of_list`. Its artifact audit and retained-version differential pass. `HashTableArrayRefinement.v` states the required array view/freshness contract and proves its get/insert/replace/remove lift to `pseq`, without assuming a target heap model. Establishing that contract for OCaml arrays remains foreign work.
- [ ] **H4.5** In progress: primitive and native-array audits inventory the private sequence realizer and standalone array workers, reject reference delegation/unsafe escapes, confine compact-child list materialization to enumeration, and check the public wrapper remains reference-backed. `hashtable-native-model-extraction-audit` verifies the generated modeled artifact is list-backed and has recursive compact-child get/set/remove workers; actual array extraction bindings remain open.
- [ ] **H4.6** In progress: `hashtable-native-array-test` and `hashtable-native-array-test-native` run retained-version reference/native histories in bytecode/native code, an explicit all-32-root-slot fill/delete-slot-31/reinsert case, a collision-heavy case-insensitive string-key scenario with functional payloads, and a 750-step randomized custom-key/function-payload retained-version differential. `hashtable-native-array-extracted-test` and its native counterpart run that retained-version differential through the array-bound extracted workers themselves. `HashMapNativeExtract.Make` passes the unchanged public wrapper and public differential suites in bytecode and native code. Broader randomized payload/custom-key coverage remains open.
- [ ] **H4.7** Switch public wrapper to native backend after passing correctness and refinement gates.
- [ ] **H4.G** Gate: modeled refinement proofs and all native checks pass; foreign/heap trust remains accurately stated.

## Deferred scope

CHAMP layout/refinement; skip/prefix nodes; custom 64-bit hashing; 32-bit OCaml
port; map/merge/union/fold extensions; ordered or
standard-library-compatible API; cryptographic collision protection; formal
expected-cost/allocation proofs; full OCaml heap/compiler verification; mandatory
physical identity reuse for unchanged updates. Each needs its own design and
acceptance criteria before adding it to the current release.
